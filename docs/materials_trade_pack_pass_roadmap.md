## Pass Strategy

1. Finish Plumbing first.

- Plumbing is the first trade with tuned scope/tier rules.
- Remaining plumbing work should focus on parser edge cases, receipt abbreviations, neighbor tests, vendor/SKU-ready slots, and review-flag reduction.
- Do not switch implementation away from Plumbing until plumbing parser coverage and diagnostics are strong enough to call that trade done.

2. Electrical is the next likely trade after Plumbing.

- Residential Electrical Core is already in the desired size band at 2,706 items.
- The electrical pass should not mainly add residential items first. It should classify light-industrial and commercial overlap correctly and add electrical receipt-neighbor tests.
- Key families: NM-B, UF-B, THHN/THWN, breakers, devices, boxes, EMT/PVC conduit, fittings, connectors, grounding, panels, lighting, disconnects, smoke/CO, smart controls.

3. HVAC likely follows Electrical.

- HVAC residential core is underweight at 853 items.
- HVAC has substantial light-industrial and commercial complete packs but empty core/standard lanes.
- Key families: filters, capacitors, contactors, thermostats, wire, condensate, refrigerant line, gas/vent, motors, RTU/service stock.

4. Smaller trades need core expansion passes.

- Many trades have Core below 300 items because generic rules are conservative.
- These need category-specific core definitions, not broad keyword flooding.
- Fasteners, tools, safety, and shared consumables should be modeled carefully so the same item can support multiple trades without uncontrolled duplication.

## Gate Before Moving To Next Trade

For each trade, do not mark it done until current evidence proves:

- all items have non-empty scope tags
- all items have tier classification
- all items have parser priority
- scoped packs are monotonic: Core <= Standard <= Professional <= Complete
- residential core is plausible for that trade, not merely non-zero
- compressed and uncompressed/on-device sizes are exposed
- parser tests cover common receipt abbreviations and neighbor families
- import/export manifest validation passes
- analyzer passes
- touched files stay near the 500-line target unless functionality requires otherwise

## Cloud Fallback Planning Note

Each pack manifest now supports both local and cloud delivery policy. Local packs are fastest and offline capable. Cloud fallback is online-only, slower, subscription-gated if enabled, may use user carrier/Wi-Fi data, and must remain read-budget aware. Do not implement cloud parsing as one Firestore read per catalog item.
