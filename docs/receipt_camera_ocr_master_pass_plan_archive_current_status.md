- **Receipt Camera Reopen Pass 464: Parser-Ready OCR Candidate Signals** is complete.
  OCR results now expose ordered parser line signals for vendor/header, date,
  item, subtotal, tax, total, and amount candidates. These signals are local
  parser inputs only; Command One telemetry must continue to receive counts and
  status buckets, not raw receipt text.
- **Receipt Camera Reopen Pass 465: Device-Tier Local Parser Scope And Cloud Assist Contract** is complete.
  Device capability plans now say exactly what local OCR/parser work is allowed
  on that phone, from vendor/date/totals-only up through local inventory
  matching. Optional cloud OCR or inventory matching remains explicit,
  internet-dependent, and represented in diagnostics by privacy-safe scope codes
  only.
- **Receipt Camera Reopen Pass 466: OCR-To-Expense Parser Handoff Guard** is complete.
  Added a focused regression proving an OCR result can expose parser-ready
  vendor, date, item, subtotal, tax, and total signals, then feed the existing
  expense parser through `appFillText` without turning address ZIP text into a
  receipt total. Also added plumber's putty/plumbing putty to the material
  keyword rules so hardware-store receipt lines route to Materials.
- **Receipt Camera Reopen Pass 467: Device-Aware OCR Result Parser Entry Point** is complete.
  Added `parseExpenseReceiptOcrResult` so the receipt flow can parse directly
  from `ReceiptOcrResult` while respecting device capability, parser depth, and
  local catalog limits. Parse diagnostics now retain OCR parser-signal counts,
  and OCR results warn when text exists but vendor, item, or total signals are
  missing.
- **Receipt Camera Reopen Pass 468: App-Assisted Flow Uses Device-Aware OCR Parser** is complete.
  The live expense receipt OCR completion path now uses
  `parseExpenseReceiptOcrResultWithLocalMemory` instead of reparsing
  `ocr.appFillText` directly. This preserves learned merchant memory when
  inventory matching is allowed, respects older-phone parser scope, and records
  `localParserScope` as privacy-safe telemetry metadata.
- **Receipt Camera Reopen Pass 469: Privacy-Safe OCR Parser Signal Health Counts** is complete.
  Receipt OCR and parser privacy events now carry content-free counts for item,
  subtotal, tax, and total candidate lines. Command One health snapshots can
  show whether OCR is detecting receipt structure without storing receipt
  images, receipt text, vendor names, prices, addresses, or line descriptions.
- **Receipt Camera Reopen Pass 470: Receipt Line Role Separation For Parser Handoff** is complete.
  The reusable OCR parser-line signal layer now separates purchased item lines
  from tender/payment lines, receipt metadata, and barcode/id-style noise. This
  keeps gift cards, auth codes, balances, and footer text out of the item list
  before expenses, inventory/materials, or later maintenance parsing consume
  the receipt.
- **Receipt Camera Reopen Pass 471: Tender And Metadata Counts Through Parser Health** is complete.
  Expense parser diagnostics and privacy-safe receipt health events now carry
  OCR tender/payment and metadata/noise line counts forward. The parser also
  rejects common gift-card/payment rows such as `MERCH/GIFT CARDS` as purchased
  items, preventing false expense lines while preserving the line as receipt
  evidence.
- **Receipt Camera Reopen Pass 472: Shared OCR Parser Handoff Object** is complete.
  Added a reusable local `ReceiptOcrParserHandoff` that groups vendor, date,
  item, summary, tender, and metadata line signals for downstream receipt
  consumers. The expense parser now reads its OCR signal counts from that
  handoff, giving materials/inventory and later maintenance a stable shared
  structure to import without rebuilding OCR classification.
- **Receipt Camera Reopen Pass 473: Normalized OCR Line Signal Fields** is complete.
  Each parser-line signal now exposes a role label, normalized matching text,
  and primary amount. This gives expense, inventory/material, and maintenance
  parsing a shared local way to ask what a line is, what amount it carries, and
  what cleaned text should be matched without duplicating OCR cleanup logic.
- **Receipt Camera Reopen Pass 474: Shared Interrupted Capture Recovery Flow** is complete.
  `ReceiptCaptureFlow` now exposes a reusable `reviewRecoveredCapture` path for
  interrupted native captures. It verifies staged photos still exist, reopens
  the same review screen with recovery diagnostics, keeps recovery if review is
  closed, discards missing recovery records, and clears the recovery manifest
  only after the recovered receipt photos are accepted.
- **Receipt Camera Reopen Pass 475: Attachment Panel Uses Shared Recovery Flow** is complete.
  The receipt attachment panel now resumes interrupted native captures through
  `ReceiptCaptureFlow.reviewRecoveredCapture` instead of duplicating recovery
  review logic. Existing attached proof, quality checks, diagnostics, module
  identity, and data-saver level are passed into the shared flow, and accepted
  recovered photos reuse the normal accepted-photo OCR handoff.
- **Receipt Camera Reopen Pass 476: Recovery Signals On OCR Source Handoff** is complete.
  OCR source attachments generated from recovered/interrupted native captures
  now include privacy-safe document signals and risk flags for resumed recovery,
  recovered photo count presence, and multiple-section recovery. This lets
  diagnostics distinguish normal captures from resumed interrupted receipt
  workflows without storing receipt text, vendors, prices, or customer content.
- **Receipt Camera Reopen Pass 477: Non-Failure Capture Diagnostic Filtering** is complete.
  Shared capture diagnostics that represent normal user outcomes, including
  accepted review, accepted recovery review, closed recovery review, review
  close, and cancel before photo, are no longer recorded as image attach
  failures. Discarded recovery and actual native capture failures still record
  through the confirmed failure path so Command One health rates do not count
  successful or intentionally closed receipt flows as failures.
- **Receipt Camera Reopen Pass 478: Parser-Ready Line Confidence Buckets** is complete.
  OCR parser line signals now carry content-local confidence and review reasons
  for vendor, date, item, subtotal, tax, total, tender, metadata, and unknown
  lines. Expense parsing and privacy-safe receipt health events now preserve
  high-confidence item-line counts separately from item lines needing review, so
  future Command One health and materials/inventory handoff can tell whether OCR
  found usable item structure without storing receipt text, prices, vendors, or
  descriptions. The material catalog matcher also now prefers explicit `wood
  screws` receipt lines over unrelated pack/size coincidences such as electrical
  screw packs.
- **Receipt Camera Reopen Pass 479: Parser Line Trait Handoff Counters** is complete.
  OCR parser line signals now carry privacy-safe structural traits such as
  price-present, quantity/unit signal, SKU-like signal, generic description,
  vendor candidate, receipt-total candidate, tender candidate, and metadata
  candidate. Expense diagnostics and the local privacy-safe Command One health
  snapshot now preserve aggregate counts for quantity/unit item lines, SKU-like
  item lines, and generic item lines, so the future parser/materials dashboard
  can tell whether OCR is producing inventory-ready structure without exposing
  receipt text, vendor names, prices, addresses, or item descriptions.
- **Receipt Camera Reopen Pass 480: OCR Summary Math Preflight** is complete.
  The OCR parser handoff now exposes primary subtotal, tax, and total lines and
  computes an internal summary-math status before the expense parser performs
  deeper receipt parsing. Expense diagnostics and privacy-safe receipt health
  events now carry only the aggregate `matched`, `mismatch`, or `incomplete`
  summary-math status plus mismatch counts, giving Command One early OCR math
  health without storing receipt amounts, merchant names, addresses, receipt
  text, or item descriptions.
- **Receipt Camera Reopen Pass 481: OCR Line Sequence Health** is complete.
  The OCR parser handoff now evaluates safe line-order health for captured
  receipts, including missing headers, missing summaries, summaries before item
  lines, tenders before summaries, and expected receipt order. Expense
  diagnostics and local privacy-safe Command One health snapshots now preserve
  only aggregate sequence status counts and review counts, so long-receipt,
  stitched-section, and out-of-order OCR problems can be diagnosed without
  storing receipt text, item descriptions, prices, addresses, or vendor names.
- **Receipt Camera Reopen Pass 482: Native Capture Recovery Safety Manifest** is complete.
  Native receipt capture staging now records explicit recovery-safety metadata
  when copied receipt photos are saved locally, including manifest backing, Hive
  recovery-index save status, local staged photo counts, local existing photo

  expose existing/missing photo counts and a privacy-safe storage status so
  interrupted camera flows can be resumed or diagnosed without storing receipt
  text, customer content, vendor names, addresses, prices, or line descriptions.
