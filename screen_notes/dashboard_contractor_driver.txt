Source: visible user message, 2026-07-23 trip tracking command-center pass

- Dashboard is the command center for the app. Trip tracking, expenses,
  materials/inventory, fuel, stops, employee/helper time, and daily records must
  talk back to the dashboard instead of behaving like isolated apps.
- The app must support different daily dashboard layouts for driver/gig users
  and individual contractors. The dashboard remains customizable, and dashboard
  settings should eventually expose additional selectable dashboard icons/widgets.
- The app needs a before-day dashboard state and an active/during-day dashboard
  state. During the day, the dashboard must show that day's stops and related
  entries.
- Individual contractor release-one focus: account owner controls the day and
  may add helpers/employees for time tracking. Fleet permissions and multi-owner
  employee permission systems are deferred, but the data model should not block
  them later.
- Export actions, including tax/CPA/accountant export, belong in the global
  hamburger menu, not the contextual screen gear settings.

Source: visible user message, 2026-07-23 commercial UX/manual-first pass

- Manual entry workflows must be complete before AI assistance is added. AI,
  GPS, Bluetooth, OCR, parsing, and ChatGPT integration are optional assistance
  layers; they must attach to complete manual records and never replace the
  user's control.
- The user is always in control. Users may use no assistance, some assistance,
  or full assistance where available. Assisted workflows must remain opt-in and
  changeable later.
- Bluetooth vehicle identification is an opt-in future assistive setup. If a
  vehicle Bluetooth system is detected/paired, it can help identify the active
  vehicle and later support automatic trip starting, but the user must set it up
  and remain able to correct the vehicle.
- Dashboard, trip tracking, expenses, fuel, materials, and helper time must
  follow one consistent commercial UI pattern. Container sizing, typography,
  action colors, spacing, and navigation behavior should not drift screen to
  screen.
